# 实施计划

> 基于 [01-product-design-doc.md](./01-product-design-doc.md) 拆解出的原子任务。每个任务包含所属模块、功能描述、技术实现要点、依赖关系、是否可并行、预计文件路径、验收标准。

***

## 阶段总览

| 阶段 | 名称                    | 依赖                | 可并行？          |
| -- | --------------------- | ----------------- | ------------- |
| P0 | 项目脚手架搭建               | 无                 | 前后端可并行        |
| P1 | 认证与基础设施               | P0                | 不可并行          |
| P2 | 独立模块 CRUD（部门/权限/系统配置） | P1                | **三个模块可相互并行** |
| P3 | 依赖模块 CRUD（菜单/角色）      | P1 + P3 中的"权限管理"  | 菜单与角色可相互并行    |
| P4 | 用户管理                  | P2(部门) + P3(角色)   | 不可并行          |
| P5 | 操作日志                  | P1 + P2 + P3 + P4 | 不可并行          |
| P6 | 集成测试与数据种子             | P5                | 不可并行          |

***

## 并行开发方案

以下分组内可并行开发，分组间按阶段顺序依赖：

```
时间轴 →
┌─────────────────────────────────────────────────────────┐
│  P0-1 后端脚手架  ◄─── 可并行 ───►  P0-2 前端脚手架    │  ← 第 1 阶段
└────────────────────┬────────────────────────────────────┘
                     │ 依赖
                     ▼
┌─────────────────────────────────────────────────────────┐
│                    P1 认证与基础设施                      │  ← 第 2 阶段（不可并行）
└─────────┬───────────────────────┬───────────────────────┘
          │ 依赖                   │ 依赖
          ▼                        ▼
┌──────────────────┐   ┌───────────────────────────────┐
│  P2-A 部门管理    │   │   P2-B 权限管理    P2-C 系统配置 │  ← 第 3 阶段
│  (P2-A1 + P2-A2) │   │   (P2-B1 + P2-B2) (P2-C1+P2-C2)│     三个模块可完全并行
└──────────────────┘   └────────────┬──────────────────┘
                                    │ 依赖 P2-B
                                    ▼
                    ┌───────────────────┐   ┌───────────────┐
                    │ P3-A 菜单管理     │   │ P3-B 角色管理  │  ← 第 4 阶段
                    │ (P3-A1 + P3-A2)   │   │ (P3-B1+P3-B2) │     可相互并行
                    └────────┬──────────┘   └───────┬───────┘
                             │ 依赖 P2-A + P3-B     │
                             ▼                      ▼
                    ┌──────────────────────────────────┐
                    │        P4 用户管理                │  ← 第 5 阶段（不可并行）
                    │    (P4-1 后端 + P4-2 前端)        │
                    └────────────────┬─────────────────┘
                                     │ 依赖
                                     ▼
                    ┌──────────────────────────────────┐
                    │       P5 操作日志                 │  ← 第 6 阶段（不可并行）
                    │    (P5-1 后端 + P5-2 前端)        │
                    └────────────────┬─────────────────┘
                                     │ 依赖
                                     ▼
                    ┌──────────────────────────────────┐
                    │  P6 集成测试 & 数据种子            │  ← 第 7 阶段
                    │  P6-2 后端测试 ── 可并行 ── P6-3  │
                    │  └ 前端测试                       │
                    └──────────────────────────────────┘
```

### 并行开发总结

| 并行组     | 包含任务                                 | 并行条件           |
| ------- | ------------------------------------ | -------------- |
| **组 1** | P0-1（后端脚手架） ↔ P0-2（前端脚手架）            | 无依赖，完全独立       |
| **组 2** | P2-A（部门管理） ↔ P2-B（权限管理） ↔ P2-C（系统配置） | 三者均只依赖 P1，互不依赖 |
| **组 3** | P3-A（菜单管理） ↔ P3-B（角色管理）              | 均依赖 P2-B，但互不依赖 |
| **组 4** | P6-2（后端测试） ↔ P6-3（前端测试）              | 独立项目，完全独立      |

**团队建议**：若有 2 名开发者，组 2 是最大化并行收益的阶段——一人负责"部门+角色+用户"（主线），另一人负责"权限+菜单+系统配置+操作日志"（另一条线）。若有 3 名开发者，组 2 的三模块可完全并行分配给三人。
